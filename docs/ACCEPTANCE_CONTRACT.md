# Agent Lens release acceptance contract v1
Frozen 2026-10-15. Baseline 2a0713d9b02a04b0b5549960e79fac0ad3d610d4.

## Supported deployment and users
Single operator on one machine, loopback-bound frontend and FastAPI, SQLite, one application worker. Non-sensitive reports and synthetic demo data only. Small local workloads; concurrent duplicate writes must fail safely without corrupting records or silently multiplying paid calls. No public exposure or direct LAN sharing. Any remote use requires authenticated SSH loopback forwarding; shared network serving is not claimed supported. This boundary must be implemented in launch configuration and verified, not merely asserted. Human reviewer labels are unverified local labels; blind review is presentation-level, not an authorization boundary.

## Required software gates
C1. Fresh documented Python 3.11+ / Node 20+ install with reproducible dependency versions; start/stop and health/configuration diagnostics. Offline mock requires no key. No existing local data or secrets touched. Full backend tests, frontend build, compile and dependency audit pass; CI checks actually execute for candidate.
C2. From empty database: record run (API acceptable), evaluate, compare prompts, independently score via browser blind queue, reveal/decide/edit, calibration drilldown, save regression case, export report. Verify empty/normal/failure/duplicate/refresh/filter/pagination/loading/error behavior. Use actual browser, synthetic data only. No unjustified missing core action.
C3. Strict finite evaluator scores 1–5 and risk boolean contract; define overall weighting and flags semantics. Reject malformed/partial/empty/semantically invalid results before persistence. Test mocked provider timeout/rate limit/auth/invalid output. Bound requests, timeout and retry/cost exposure. Keep report content untrusted within judge instructions; representative injection fixtures. Scores do not verify external truth. Failures visible, unevaluated not zero.
C4. Preserve exact evaluation bindings, rubric and model scopes, foreign keys/uniqueness/atomicity, immutable run input/output metadata sufficient to interpret comparisons. Comparisons expose matched-input coverage, unpaired samples, mixed workflows/models/judges, retries and denominators; no causal improvement claims from unmatched cohorts. Prompt/dataset/experiment registries are non-goals but absent provenance must be explicit.
C5. Blind queue and pre-submit detail payload/UI omit judge scores/flags/rankings; refresh does not silently change reviewed evaluation. Post-reveal edits retain provenance and are not counted as independent blind evidence. Golden hand-computed calibration covers MAE/RMSE/bias/agreement/correlation/coverage/acceptance, empty/single/constant/missing/duplicate/multi-review/model/rubric/boundary cases. Consensus gives each evaluation equal weight. Undefined metrics null; sample counts and limitations visible.
C6. Cost in USD; caller-reported generation cost/token/latency distinguished from judge/retry overhead and mock estimates. Unknown cost/latency cannot be zero; means expose denominators and exclude missing values. Charts and report share date/filter scope, failed-run handling and aggregation definitions.
C7. Implement and verify local access boundary, safe text rendering, secret/error handling, bounded request sizes, SQLite foreign keys and safe persistence. Test supported legacy schema upgrade, atomic failure, backup/restore and repeat startup/seed; never overwrite existing user data. Documentation identifies unsupported schemas and recovery. No claim of authentication, encryption, redaction or isolation absent implementation.
C8. README (including Chinese), configuration example, API docs, changelog, operations/backup/rollback and release checklist agree with code. Provide deterministic experiment fixture/script with controlled prompt pairs, holdout separation and preserved metadata. Real provider integration and real human effectiveness remain separately UNVERIFIED without explicit budget/human evidence; never fabricate or spend.
C9. No open P0/P1. P2 deferral requires named human acceptance, impact and follow-up; absent approval it remains unresolved. Final candidate requires two fresh-context independent PASS reports on exact full SHA + base SHA + this contract, global acceptance plus all cumulative diff, followed by separate reconciliation of historical findings. Any critical unverified software gate blocks readiness. New pushes invalidate approvals; no merge/release/deploy.

## Review protocol and evidence
First independently write immutable phase-1 reports in external output directory, before receiving other findings or implementation discussion. Record role/session ID/actual model if exposed (otherwise explicitly unavailable), exact SHAs/contract hash, fork_turns=none and exposure, inspected scope, actual commands/results, evidence paths, structured findings with ID/P0-P3/file/line/expected/actual/reproduction/impact/test/status, unknowns and PASS|CHANGES_REQUIRED|UNVERIFIED. Then reconcile shared historical ledger independently and append phase-2 report without overwriting phase 1. Neither author nor QA is an independent approver. Four concurrent slots require staggered scheduling of the five responsibilities; disclose this platform limit. No simulated reviewers or native identity claims. Reports outside source; no self-approval check in reviewed branch.
